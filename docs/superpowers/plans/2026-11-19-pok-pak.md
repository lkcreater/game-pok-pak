# Pok Pak Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browser brick-breaker (many balls, item drops, ASCII levels, stars + best score in localStorage) on Next.js 16, plus a Claude Stop hook that keeps docs current.

**Architecture:** Pure TypeScript game logic in `lib/` (no DOM, fully unit-tested): level parsing, item registry, scoring, save, and a `Game` engine stepped at a fixed timestep. One client component renders the engine to a Canvas 2D; another drives the screen flow (name → level select → play → result). React never touches per-frame state.

**Tech Stack:** Next.js 16.4.6 (App Router, TypeScript, Turbopack), React 19, Vitest, plain CSS, bash hook.

**Spec:** `docs/superpowers/specs/2026-11-19-pok-pak-design.md` (Thai). Read it before any task.

## Global Constraints

- Next.js `16.4.6`, TypeScript, App Router, no `src/` dir, import alias `@/*`, npm.
- No game engine (no Phaser/Pixi), no Tailwind. Only added dependency: `vitest` (dev).
- Everything in `lib/` is DOM-free and deterministic given an injected `rng: () => number`.
- localStorage key `pokpak:v1`; every read/write wrapped in try/catch; the game must work when storage throws.
- Adding a level = one entry in `lib/game/levels.ts`. Adding an item = one entry in `lib/game/items.ts`. No other file may need edits for either.
- Map legend: `#` indestructible wall, `B` brick (1 hit), `.` empty.
- Constants (in `lib/game/constants.ts`): `CELL = 12`, `BALL_SPEED = 360` (px/s), `FIXED_DT = 1/120`, `BALL_RADIUS = 3`, `PADDLE_W = 72`, `PADDLE_H = 8`, `PADDLE_STEP = 0.25` (fraction of `PADDLE_W` per `growPaddle` step), `PADDLE_MAX = 2` (× `PADDLE_W`), `MAX_BALLS = 500`, `DROP_SPEED = 150`, `DROP_RADIUS = 9`, `DEFAULT_DROP_CHANCE = 0.02`, `MIN_VY_RATIO = 0.25`, `MAX_BOUNCE_DEG = 60`, `PADDLE_ZONE = 0.35` (fraction of world height below the map).
- Score: brick `+10`, caught item `+50`, on win `+ floor(max(0, par − elapsedSeconds) × 20)`.
- Stars: win = 1, `score ≥ stars[0]` = 2, `score ≥ stars[1]` = 3. Loss = 0 and nothing saved.
- Unlock: level 0 always; level i when level i−1 has ≥ 1 star.
- UI copy in Thai.

## Review Focus

1. **Diagonal corner hit** — a ball moving diagonally into a brick touching only at a corner must bounce/break, never tunnel. Test in Task 3.
2. **Huge frame gaps** (tab backgrounded, debugger pause) — loop must clamp real dt to 0.1 s and run at most that many fixed steps; no tunnelling, no freeze. Pinned in Task 6 (clamp) + Task 3 (step never moves > CELL/2).
3. **Corrupt or throwing localStorage** — invalid JSON, wrong shape, `getItem` throwing → defaults, no crash. Test in Task 5.
4. **Repeated `x3` near the cap** — ball count never exceeds `MAX_BALLS`. Test in Task 4.
5. **More guaranteed items than bricks / ball hitting paddle underside** — extra items silently ignored; ball moving upward through the paddle is not reflected. Tests in Tasks 4 and 3.

### Task 3: Game engine — physics, paddle, win/lose

**Files:**
- Create: `lib/game/engine.ts`
- Test: `lib/game/engine.test.ts`

**Interfaces:**
- Consumes: `Grid`, `parseMap`, `cellAt`, `Cell`, `Level`, `ITEMS`, `GameActions`, `timeBonus`, constants.
- Produces:
  ```ts
  export type Ball = { x: number; y: number; vx: number; vy: number };
  export type Drop = { x: number; y: number; item: ItemId };
  export type Status = 'ready' | 'playing' | 'won' | 'lost';
  export class Game implements GameActions {
    constructor(level: Level, rng?: () => number);
    readonly level: Level; readonly grid: Grid;
    readonly width: number;   // grid.cols * CELL
    readonly height: number;  // round(grid.rows * CELL / (1 - PADDLE_ZONE))
    readonly paddleY: number; // height - 40 (top edge of paddle)
    balls: Ball[]; drops: Drop[];
    paddle: { x: number; w: number };  // x = center
    score: number; elapsed: number; status: Status; fireLeft: number;
    bricksLeft: number;
    brokenCells: number[];   // indices of cells broken since last drained; renderer drains it
    setPaddleX(x: number): void;   // clamps so paddle stays inside [0, width]
    launch(): void;                // 'ready' → 'playing'
    step(): void;                  // advance exactly FIXED_DT; no-op unless 'playing'
    // GameActions methods implemented in Task 4 (stubs that throw are fine here)
  }
  ```

Physics rules (the step algorithm — not determined by the signature):
- In `ready`, balls sit on the paddle (spread across its top) and follow it. `launch()` gives them velocities spread evenly within ±30° of straight up, magnitude `BALL_SPEED`.
- Per ball per step: move along x first: `nx = x + vx*dt`; if `nx` outside `[0,width]` → `vx = -vx`; else if `cellAt(col(nx), row(y))` is Wall → `vx = -vx`; Brick → break it (score +10, push index, `bricksLeft--`, Task 4 drop hook) and `vx = -vx` unless `fireLeft > 0`; else `x = nx`. Then the same for y using the already-updated x (this is what catches diagonal corners). `y < 0` → reflect; `y > height` → remove ball. Collision treats the ball as its center point (`ponytail:` comment: radius ignored for cells; switch to swept circle if edges look wrong).
- Paddle: if `vy > 0` and the ball crosses `paddleY` this step with `|x - paddle.x| ≤ paddle.w/2` → `offset = (x - paddle.x)/(paddle.w/2)`, angle `offset × MAX_BOUNCE_DEG` from vertical, `vy` negative, speed `BALL_SPEED`. Upward-moving balls ignore the paddle.
- After any reflection, if `|vy| < MIN_VY_RATIO × BALL_SPEED`, set `|vy|` to that (keep sign) and renormalise to `BALL_SPEED`.
- `elapsed += dt` while playing; `fireLeft = max(0, fireLeft - dt)`.
- `bricksLeft === 0` → `status = 'won'`, `score += timeBonus(level.par, elapsed)`. `balls.length === 0` while playing → `'lost'`.

### Task 4: Game engine — items and drops

**Files:**
- Modify: `lib/game/engine.ts`
- Test: `lib/game/engine.items.test.ts`

**Interfaces:**
- Consumes: Task 3 `Game`, `ITEMS`, `ItemId`.
- Produces: `Game` fully implements `GameActions`; `game.hidden: Map<number, ItemId>` (cell index → guaranteed item).

Rules:
- Constructor: shuffle brick indices with `rng`, assign each `level.items.guaranteed[i]` to a distinct brick; extras beyond the brick count are ignored.
- On brick break: if `hidden` has the index → spawn `Drop` at cell center; else if `pool` non-empty and `rng() < (dropChance ?? DEFAULT_DROP_CHANCE)` → spawn a uniformly random pool entry.
- Drops fall at `DROP_SPEED`; caught when the drop circle overlaps the paddle rect → `ITEMS[item].apply(this)`, `score += 50`, removed; removed when `y > height`.
- `multiplyBalls(n)`: each existing ball gets `n−1` copies with velocity rotated by `±15°, ±30°…`; total capped at `MAX_BALLS`.
- `addBalls(n)`: n new balls at paddle center top, angles spread within ±20° of up; capped.
- `growPaddle(steps)`: `w = min(PADDLE_W*PADDLE_MAX, w + steps*PADDLE_STEP*PADDLE_W)`, permanent for the level.
- `setFire(s)`: `fireLeft = s` (reset, not add).

Hook algorithm (`docs-check.sh`, bash, macOS-compatible, no `jq`):
```bash
#!/usr/bin/env bash
input=$(cat)
[[ $input =~ \"stop_hook_active\"[[:space:]]*:[[:space:]]*true ]] && exit 0
cd "${CLAUDE_PROJECT_DIR:-$(dirname "$0")/../..}" || exit 0
marker=.claude/.docs-checked
ref=""                                   # newest of docs + marker
for f in docs/spec.md docs/decisions.md CLAUDE.md "$marker"; do
  [[ -f $f ]] && { [[ -z $ref || $f -nt $ref ]] && ref=$f; }
done
stale=0
while IFS= read -r line; do
  f=${line:3}; f=${f##* -> }; f=${f%\"}; f=${f#\"}
  case $f in docs/*|CLAUDE.md|.claude/.docs-checked) continue;; esac
  [[ -f $f ]] || continue
  if [[ -z $ref || $f -nt $ref ]]; then stale=1; break; fi
```
