# Pok Pak (ป๊อกแป๊ก) — Design

วันที่: 2026-11-19 · สถานะ: รออนุมัติ (แก้ตามรีวิวแล้ว)

## Intent / ทำไม

เกมแนว brick breaker สำหรับเจ้าของ repo เล่นเองคนเดียว แรงบันดาลใจจากคลิปเกมแนว "บล็อกเต็มจอ + ลูกบอลหลายสิบลูก":
กระดานบล็อกเหลืองหนาแน่นในกรอบกำแพงเทา กรอบมีช่องเปิดกลางบน/ล่าง ลูกบอลขาวจำนวนมากเจาะบล็อกเป็นโพรง
ผู้เล่นคุมแป้นแดงด้านล่าง รับไอเทมที่ดรอปลงมา ความสนุกหลักคือความ "สะใจ" ตอนลูกบอลทวีคูณแล้วกัดกินบล็อก

ใช้กลไกของ genre แต่ชื่อ หน้าตา และสีเป็นของเราเอง ไม่ลอกเกมต้นทาง

## Goals

- เล่นได้ใน browser (desktop เมาส์/คีย์บอร์ด และมือถือแบบสัมผัส)
- ก่อนเล่นกรอกชื่อ มีชื่อสุ่มตั้งต้นให้ (เช่น `SwiftComet-482`) กดสุ่มใหม่หรือแก้เองได้
- ระบบด่านที่เพิ่มด่านใหม่ได้ง่าย: เพิ่ม entry เดียวในไฟล์ `levels.ts`
- รางวัล: ไอเทมระหว่างเล่น + ดาว 1–3 ดวงและ best score ต่อด่าน
- จำความคืบหน้า (ชื่อ, ดาว, best score, ด่านที่ปลดล็อก) ไว้ใน localStorage
- Claude Stop hook ที่เตือนให้อัปเดต spec / decisions / CLAUDE.md / memory หลังแก้โค้ด

## Non-goals

- ไม่มี backend, บัญชีผู้ใช้, leaderboard ออนไลน์
- ไม่มีเหรียญ ร้านค้า สกิน (ผู้ใช้ยืนยันว่าดาว + best score พอ)
- ไม่มี level editor (เพิ่มด่านด้วยการแก้ `levels.ts`)
- ไม่มีเสียง / เพลง ในรอบแรก

## Anti-goals (ถ้าเป็นแบบนี้ถือว่าล้มเหลว แม้จะทำงานได้)

- กระตุก เมื่อมีบล็อก ~1,600 ก้อน และลูกบอลหลายร้อยลูก — ต้องลื่นที่ 60fps บนแล็ปท็อปทั่วไป
- ลูกบอลทะลุกำแพง/ติดอยู่ในบล็อก
- เพิ่มด่านใหม่แล้วต้องแก้โค้ดส่วนอื่นนอกจาก `levels.ts`
- ข้อมูลเซฟพังแล้วทำให้เกมเปิดไม่ได้

## Constraints

- Next.js ตัวล่าสุด (16.4.6 ณ วันที่เขียน), App Router, TypeScript
- Node 24 บนเครื่องผู้ใช้
- ไม่ใช้ game engine (Phaser/Pixi) — ดู Approaches
- เก็บข้อมูลเฉพาะ localStorage; ทุกการอ่าน/เขียนห่อด้วย try/catch และ fallback เป็นค่าเริ่มต้นได้เสมอ

## Approaches

| เรื่อง | ทางเลือก | ข้อแลกเปลี่ยน | เลือก |
|---|---|---|---|
| Rendering | **Canvas 2D ใน client component** | ลื่นกับบล็อกพันกว่าก้อน ไม่ต้องลง dependency | ✅ |
| | React วาด `<div>` ทุกบล็อก | เขียนง่าย แต่ 1,600 element อัปเดตทุกเฟรมจะกระตุก | |
| | Phaser / PixiJS | ได้ physics/effect สำเร็จรูป แต่หนักเกินขนาดงาน | |
| เพิ่มด่าน | **แผนที่ ASCII ใน `levels.ts`** | เห็นหน้าตาด่านในโค้ด เพิ่มด่าน = เพิ่ม entry | ✅ |
| | JSON + level editor | สร้างด่านสะดวก แต่งานเพิ่มเกือบเท่าตัว | |

## Design

### หน้าจอ (state machine ในหน้าเดียว `/`)

```
[ใส่ชื่อ] → [เลือกด่าน] → [ในเกม] → [ผลด่าน] → (ด่านถัดไป | เล่นซ้ำ | กลับเลือกด่าน)
```

- **ใส่ชื่อ**: แสดงครั้งแรก หรือเมื่อยังไม่มีชื่อในเซฟ ช่องชื่อเติมชื่อสุ่มให้ (คำคุณศัพท์ + คำนาม + เลข 3 หลัก จากลิสต์คำเล็กๆ ในโค้ด), ปุ่ม 🎲 สุ่มใหม่, ปุ่มเริ่ม ชื่อว่างไม่ได้ (trim, ยาวสุด 20 ตัว) หน้าเลือกด่านมีปุ่มเปลี่ยนชื่อกลับมาหน้านี้
- **เลือกด่าน**: ปุ่มด่านเรียงตามลำดับใน `levels.ts` แสดงดาวและ best score ด่านที่ล็อกแสดง 🔒 กดไม่ได้
- **ในเกม**: canvas + HUD (ชื่อ, ด่าน, คะแนน, เวลา, จำนวนลูก) ปุ่ม pause
- **ผลด่าน**: ผ่าน/ไม่ผ่าน, คะแนน, ดาว, best score, ปุ่ม ต่อ (เฉพาะเมื่อผ่านและมีด่านถัดไป) / เล่นซ้ำ / เลือกด่าน

### การนิยามด่าน (`levels.ts`)

```ts
type Level = {
  id: string;           // คงที่ ใช้เป็น key ในเซฟ — ห้ามเปลี่ยนหลังปล่อย
  name: string;
  map: string[];        // แต่ละแถวคือ string ความยาวเท่ากัน
  balls: number;        // จำนวนลูกตอนเริ่ม (ยิงออกพร้อมกันทั้งหมด ไม่มีลูกสำรอง)
  par: number;          // วินาทีเป้าหมาย ใช้คำนวณ time bonus
  stars: [number, number]; // คะแนนขั้นต่ำสำหรับ 2 ดาว และ 3 ดาว
  items?: {
    guaranteed?: ItemId[]; // ไอเทมการันตี: แต่ละชิ้นซ่อนในบล็อกสุ่ม 1 ก้อน แตกแล้วดรอปแน่นอน
    pool?: ItemId[];       // ไอเทมที่สุ่มดรอปได้จากบล็อกอื่นๆ (ซ้ำชื่อ = น้ำหนักมากขึ้น)
    dropChance?: number;   // โอกาสดรอปจาก pool ต่อบล็อก, ค่าเริ่มต้น 0.02
  };
};
```

ตัวอย่าง: `items: { guaranteed: ['x3', 'up1', 'boardx1'], pool: ['up3', 'up3', 'fire'] }`
ไม่ระบุ `items` = ไม่มีไอเทมในด่านนั้น `ItemId` เป็น type ที่ได้จากทะเบียนไอเทม พิมพ์รหัสผิดใน `levels.ts` → TypeScript error ตอน build

สัญลักษณ์ในแผนที่: `#` กำแพงทำลายไม่ได้, `B` บล็อก (แตกในครั้งเดียว), `.` ที่ว่าง
ลำดับใน array = ลำดับด่าน การเพิ่มสัญลักษณ์ใหม่ (เช่นบล็อกแข็ง 2 ครั้ง) ทำได้ทีหลังโดยเพิ่มใน legend ที่เดียว

รอบแรกส่งมา 3 ด่าน:
1. แบบภาพอ้างอิง: บล็อกเต็มสี่เหลี่ยมในกรอบกำแพง มีช่องเปิดกลางบนและล่าง
2. และ 3. รูปทรงอื่นที่ต่างกันชัดเจน (เช่น เพชร/หลายห้อง) — ผู้สร้างออกแบบเอง

### โลกของเกม

- ขนาดโลกเชิงตรรกะคงที่แนวตั้ง (กว้าง = คอลัมน์ของแผนที่ × ขนาดเซลล์; ใต้แผนที่มีพื้นที่ว่างสำหรับแป้น ~35% ของความสูง)
  scale ให้พอดี viewport โดยคงอัตราส่วน (letterbox)
- ขอบซ้าย ขวา บนของโลกเป็นกำแพง ขอบล่างเปิด — ลูกที่ตกพ้นขอบล่างหายไป
- ลูกที่หลุดออกจากกรอบทางช่องบนเด้งอยู่ระหว่างกรอบกับขอบโลกได้ (ตามภาพอ้างอิง)
- ไม่มีการชนระหว่างลูกบอลด้วยกัน
- ลูกบอลวิ่งความเร็วคงที่ เคลื่อนแบบ sub-step ไม่เกินครึ่งเซลล์ต่อ step ตรวจชนกับเซลล์ในตารางแยกแกน x/y เพื่อรู้ว่าต้องสะท้อนแกนไหน → ไม่ทะลุ ไม่ติด
- กันลูกวิ่งเกือบแนวนอน/แนวตั้งตลอดไป: มุมมีขั้นต่ำจากแกน
- แป้น: มุมสะท้อนขึ้นกับตำแหน่งที่โดนบนแป้น (กลาง = ตรงขึ้น, ขอบ = เฉียง)
- ควบคุม: เมาส์/นิ้วลากเพื่อเลื่อนแป้นแนวนอน, คีย์ ←/→ ก็ได้ เริ่มด่านลูกจะเกาะอยู่บนแป้น คลิก/แตะ/Space เพื่อยิง
- Pause อัตโนมัติเมื่อแท็บถูกซ่อน, Esc/P สลับ pause

### ไอเทม (รางวัลระหว่างเล่น)

ไอเทมมาจากสองทาง (ดู `items` ในการนิยามด่าน): ชิ้นการันตีที่ซ่อนในบล็อกสุ่ม และการสุ่มดรอปจาก pool
ไอเทมตกลงตรงๆ เป็นวงกลมมีป้าย (ตามภาพอ้างอิง) รับด้วยแป้นถึงได้ผล ตกพ้นจอ = หายไป

**ทะเบียนไอเทม (`items.ts`) — เพิ่มไอเทมใหม่ = เพิ่ม entry เดียว**

```ts
type ItemDef = {
  label: string;               // ข้อความบนวงกลม เช่น '×3'
  color: string;
  apply: (game: GameActions) => void;
};

const ITEMS = {
  x2:      { label: '×2',  color: …, apply: g => g.multiplyBalls(2) },
  x3:      { label: '×3',  color: …, apply: g => g.multiplyBalls(3) },
  up1:     { label: '+1',  color: …, apply: g => g.addBalls(1) },
  up3:     { label: '+3',  color: …, apply: g => g.addBalls(3) },
  boardx1: { label: '<->', color: …, apply: g => g.growPaddle(1) },
  fire:    { label: '🔥',  color: …, apply: g => g.setFire(8) },
} satisfies Record<string, ItemDef>;

type ItemId = keyof typeof ITEMS;
```

`GameActions` คือชุดคำสั่งเล็กๆ ที่เกมเปิดให้ไอเทมเรียก ไอเทมใหม่ที่ใช้คำสั่งเดิมได้ = เพิ่ม entry อย่างเดียว
ไอเทมที่ต้องการพฤติกรรมใหม่ = เพิ่มคำสั่งใน `GameActions` หนึ่งตัว แล้วเพิ่ม entry

| คำสั่ง | ผล |
|---|---|
| `multiplyBalls(n)` | ลูกทุกลูกบนจอแตกเป็น n ลูก (ลูกใหม่เบนมุมออกจากลูกเดิมเล็กน้อย) |
| `addBalls(n)` | ยิงลูกใหม่ n ลูกจากแป้นขึ้นไปทำมุมกระจาย |
| `growPaddle(steps)` | แป้นยาวขึ้น steps ขั้น (ขั้นละ +25% ของความยาวตั้งต้น) อยู่ถึงจบด่าน ยาวสุด 2 เท่า |
| `setFire(sec)` | ลูกทุกลูกเจาะทะลุบล็อก (แตกแต่ไม่สะท้อน) sec วินาที รับซ้ำ = รีเซ็ตเวลา; ยังสะท้อนกับกำแพง |

จำนวนลูกบนจอมีเพดาน (ค่าเริ่มต้น 500) เพื่อกันประสิทธิภาพตก ลูกที่เกินเพดานจะถูกตัดทิ้ง

### คะแนนและดาว

- บล็อกแตก +10, รับไอเทม +50
- ผ่านด่าน (บล็อก `B` หมด): time bonus = `max(0, par − วินาทีที่ใช้) × 20`
- ดาว: ผ่าน = 1 ดาว, คะแนน ≥ `stars[0]` = 2 ดาว, ≥ `stars[1]` = 3 ดาว
- แพ้ (ลูกหมด) = 0 ดาว ไม่บันทึกอะไร
- ผ่านแล้ว: อัปเดต best score และดาวแบบเก็บค่าสูงสุด (ไม่ลดลง)

### การปลดล็อก

ด่านแรกปลดล็อกเสมอ ด่าน i ปลดล็อกเมื่อด่าน i−1 มีดาว ≥ 1 (คำนวณจากเซฟ ไม่เก็บแยก)

### เซฟ (localStorage)

key เดียว `pokpak:v1`:

```json
{ "name": "SwiftComet-482", "levels": { "<levelId>": { "best": 1580, "stars": 2 } } }
```

อ่านแล้ว parse ไม่ได้ / รูปร่างไม่ตรง → ใช้ค่าเริ่มต้น (ไม่ throw) localStorage ใช้ไม่ได้ → เกมยังเล่นได้ แค่ไม่จำ

### Rendering

- กำแพงและบล็อกวาดลง offscreen canvas ครั้งเดียว แล้วลบเฉพาะเซลล์ที่แตก; ทุกเฟรม blit ภาพนั้น + วาดลูก แป้น ไอเทม
- game loop ด้วย `requestAnimationFrame`, fixed timestep สำหรับ physics (กัน frame rate ต่างกันแล้วเกมเร็วช้าต่างกัน)
- state ของเกมอยู่นอก React (ใน ref/คลาสธรรมดา) React ดูแลแค่หน้าจอและ HUD (อัปเดต HUD ไม่ถี่กว่า ~10 ครั้ง/วินาที)
- โทนสี: พื้นเข้ม, บล็อกเหลือง, กำแพงเทา, ลูกขาว, แป้นแดง (ตามบรรยากาศภาพอ้างอิง) — รายละเอียดสีเป็นของผู้สร้าง

### Logic ที่ต้องมี test

ส่วนที่เป็นตรรกะล้วนแยกเป็นโมดูลไม่พึ่ง DOM: parse ด่าน, step ของ physics (สะท้อนกำแพง/บล็อก/แป้น, ไม่ทะลุ), คะแนน/ดาว, การปลดล็อก, อ่าน/เขียนเซฟ (รวมกรณีเซฟเสีย), สุ่มชื่อ
มี test ชุดเล็กครอบคลุมสิ่งเหล่านี้ และ `levels.ts` มี test ตรวจทุกด่าน: แถวยาวเท่ากัน, สัญลักษณ์ถูกต้อง, `id` ไม่ซ้ำ, มีบล็อกอย่างน้อย 1, `stars[0] < stars[1]`

### เอกสารโปรเจกต์ + Claude hook

ไฟล์ที่ต้องมีและดูแลต่อเนื่อง:

- `CLAUDE.md` — วิธีรัน/test, โครงไฟล์, วิธีเพิ่มด่าน, กติกาการอัปเดตเอกสาร
- `docs/spec.md` — สเปกเกมปัจจุบัน (living doc, เริ่มจากเนื้อหาของ design นี้)
- `docs/decisions.md` — บันทึกการตัดสินใจ (วันที่, เรื่อง, ตัดสินใจอะไร, เพราะอะไร) เริ่มจากตาราง Approaches ข้างบน
- memory ของ Claude สำหรับโปรเจกต์นี้ (อยู่นอก repo ใน `~/.claude/projects/.../memory/`)

Hook (`.claude/settings.json` → `Stop` → `.claude/hooks/docs-check.sh`, commit ลง repo):

1. อ่าน JSON จาก stdin; ถ้า `stop_hook_active` เป็น true → ออก 0 (กันวนลูป)
2. ดูไฟล์ที่เปลี่ยนจาก `git status --porcelain` ถ้ามีไฟล์โค้ด/config (นอก `docs/` และ `CLAUDE.md`) ที่ถูกแก้**หลัง**ไฟล์ล่าสุดในบรรดา `docs/spec.md`, `docs/decisions.md`, `CLAUDE.md` (เทียบเวลาแก้ไฟล์)
   — ใช้เวลาแก้ไฟล์แทนแค่ "อยู่ใน git status หรือไม่" เพื่อไม่ให้ hook เงียบไปตลอดเมื่อ docs มีการแก้ค้างอยู่ก่อนแล้ว
3. → พิมพ์ `{"decision":"block","reason":"..."}` ให้ Claude ทบทวนว่าการเปลี่ยนแปลงนี้กระทบ spec / ต้องบันทึก decision / ต้องแก้ CLAUDE.md / มีอะไรควรจำใน memory หรือไม่ แล้วอัปเดตเท่าที่จำเป็น (ถ้าไม่มีอะไรต้องอัปเดต ให้บอกเหตุผลสั้นๆ แล้วจบได้)
4. กรณีอื่น → ออก 0 เงียบๆ

## การตัดสินใจหลังรีวิว

- (ผู้ใช้) ระบบไอเทมแบบทะเบียนกลาง ขยายง่าย มีไอเทมคูณลูก (`x3` = ลูกทุกลูก ×3) และด่านระบุไอเทมได้ทั้งแบบการันตีและแบบ pool สุ่ม
- (Claude) `balls` = ยิงออกพร้อมกันทั้งหมด ไม่มีลูกสำรอง; แพ้เมื่อลูกบนจอหมด — ตรงกับภาพอ้างอิงที่เน้นลูกจำนวนมาก
- (Claude) `boardx1` = แป้นยาวขึ้นถาวรจนจบด่าน (ไม่จับเวลา) ง่ายกว่าและไม่ต้องมี HUD นับเวลา
- (Claude) Docs hook เทียบเวลาแก้ไฟล์ ไม่ใช่แค่ git status

## ทิ้งไว้ให้ผู้สร้างตัดสินใจ

- ขนาดเซลล์, ความเร็วลูก, ขนาดแป้น, ตัวเลขดาว/par ของแต่ละด่าน (จูนจากการเล่นจริง)
